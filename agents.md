# AGENT.MD: Xanso AI Wellness Concierge Specification

**Project:** Xanso Digital Fitness & Wellness Platform
**Focus:** AI Agent Architecture, Persona, and LangGraph Implementation
**Target Audience:** Full-Stack & AI Engineers

This document defines the behavior, logic, and technical integration of the Xanso AI Wellness Concierge. Designed as an intelligent, stateful agent, it leverages LangChain and LangGraph to manage dynamic conversations, process wellness assessments, and trigger REST API workflows.

---

## 1. Agent Persona & Tone Design

The Xanso Concierge is a premium, empathetic, and highly efficient fitness guide. It is not a generic "customer support bot." 

*   **Role:** Expert Personal Trainer & Wellness Guide.
*   **Tone:** Encouraging, concise, action-oriented, and professional. 
*   **Vibe:** Premium luxury fitness club manager.
*   **Formatting Rules:** 
    *   Keep responses under 3-4 sentences.
    *   Use bullet points for workout suggestions.
    *   Always end with a clear Call to Action (CTA) or a deep link (e.g., `[Start 15-Min Mobility](#)`).

3. LangGraph Architecture (Workflow & State)
Because Xanso requires a stateful agent (handling the 8-question Wellness Assessment or multi-step booking), a cyclic graph (LangGraph) is superior to a standard linear chain.

A. Graph State Schema (TypeScript representation)
The agent will maintain a state object during the session to eliminate repetitive questions.

TypeScript
import { BaseMessage } from "@langchain/core/messages";

export interface AgentState {
  messages: BaseMessage[];
  userId: string;
  intent: "casual_chat" | "assessment" | "booking" | "support";
  assessmentProgress: {
    currentQuestionIndex: number;
    answers: Record<string, string>;
    isComplete: boolean;
  };
  recommendedProgramId: string | null;
}
B. Graph Nodes (Logic Flow)
ClassifierNode: Analyzes the user's first message to determine the intent.

AssessmentNode: If intent === 'assessment', this node loops through the 8 questions, saving answers to the state via API calls to the Supabase backend.

RAG_Node: If the user asks about platform features or fitness advice, this node queries the vector database (pgvector in Supabase) for specific Xanso content.

ToolExecutionNode: Triggers specific backend REST APIs based on LLM function calls.

4. Agent Tools (Function Calling)
The agent must be equipped with the following tools to interact with the platform database. Each tool triggers a backend REST API endpoint.

Tool 1: search_xanso_programs
Description: Searches the on-demand library based on time, intensity, and category.

Parameters:

category (string): e.g., "Yoga", "HIIT", "Meditation"

duration_max (number): Max time in minutes (e.g., 15, 30, 60)

level (string): "Beginner", "Intermediate", "Advanced"

Tool 2: fetch_live_schedule
Description: Retrieves today's available live trainer-led classes.

Parameters:

timezone (string): The user's local timezone.

class_type (string): e.g., "Group", "1:1"

Tool 3: save_wellness_assessment
Description: Commits the user's completed assessment to the Supabase PostgreSQL database to update their global profile.

Parameters:

user_id (string)

primary_goal (string)

fitness_level (string)
